# Error analysis

This section distinguishes observed behavior from proposed benchmark inspection. Generated `metrics.json` provides every incorrect held-out example’s index, actual class, prediction, confidence and uncertainty without redistributing raw dataset text. Reconstruct examples locally from `data/cache/<task>.json` using their cleaned test indices.

## Qualitative probes to reproduce

| Phenomenon | Newly authored text | Expected limitation |
|---|---|---|
| Negation | I am not happy with this result. | Rules use only three tokens of scope; longer-distance negation can fail |
| Sarcasm | Great. Another two hours stuck in traffic. | Positive lexicon can override sarcastic intent |
| Mixed emotions | I am happy but worried about tomorrow. | Single-label models compress mixed states |
| Slang | This is sick, I love it. | Context-dependent slang may be misread |
| Misspelling | I am sooo happpy. | Lexicon misses altered spelling |
| Domain shift | Costs fell while revenue remained unchanged. | Financial polarity depends on investor context |
| Code mixing | Aaj main bahut खुश hoon. | Unicode support does not establish multilingual validity |

Baseline probes are covered by tests where behavior is definite. Run transformer probes locally with `ENABLE_TRANSFORMERS=1`; qualitative transformer outcomes are not asserted without a measured run. No rules are changed based on held-out benchmark errors during this build.

## Interpreting generated reports

Compare false positives and false negatives per class in the error index view, inspect high-confidence mistakes, and consider class imbalance. Unknown rule emotion counts as an incorrect prediction. Rule support is not calibrated probability; ECE describes observed score behavior, not a guarantee. Future work should review representative error texts locally and annotate linguistic phenomena with a protocol defined before tuning.
